# Roadmap

The initial standalone approval-first implementation is tracked in [#1](https://github.com/omniaura/infinite-disk/issues/1) and [PR #2](https://github.com/omniaura/infinite-disk/pull/2).

| Priority | Capability | Tracker |
| --- | --- | --- |
| P0 | Project-by-project review, source-upload consent, trusted host approvals | [#3](https://github.com/omniaura/infinite-disk/issues/3) |
| P0 | Provider-native stale worktree lifecycle and complete recovery | [#6](https://github.com/omniaura/infinite-disk/issues/6) |
| P1 | Ditto Desktop integration using the standalone contract | [#4](https://github.com/omniaura/infinite-disk/issues/4) |
| P1 | Private encrypted archives and coding-session offload | [#7](https://github.com/omniaura/infinite-disk/issues/7) |
| P1 | Storage-growth attribution and preventive producer budgets | [#8](https://github.com/omniaura/infinite-disk/issues/8) |
| P1 | Secure credentials, hard AI spend budgets, OS containment | [#9](https://github.com/omniaura/infinite-disk/issues/9) |
| P2 | Native menu-bar/taskbar status companion | [#5](https://github.com/omniaura/infinite-disk/issues/5) |
| P2 | Multi-volume monitoring and broader platform/service proof | [#10](https://github.com/omniaura/infinite-disk/issues/10) |

Core approval gates are already implemented; #3 extends the experience and host authorization rather than deferring safety. Roadmap scope is not a claim of existing capability. No roadmap item implicitly authorizes autonomous deletion or private-history upload.
